## Known limitations

- Live MongoDB and a live Cloudflare `wrangler dev` / browser runtime were unavailable because `.env` and `.dev.vars` are absent and `MONGODB_URI`, `SESSION_SECRET`, and `ADMIN_*` are unset. Persistence, runtime parity, and UI scenarios were executed against the real Express app, Cloudflare Worker `fetch` handler, and React components backed by an in-memory `MongoClient` stub.
- Pre-existing Express static-middleware behavior: when `web/dist/index.html` exists on disk and Express runs with `dev: false`, `express.static(path.join(webDir, "dist"))` serves `web/dist/index.html` (HTTP 200) on `GET /` before `app.get("/", ...)` can emit HTTP 302 (after which client-side `<Route path="/" element={<Navigate to="/dashboard" replace />} />` navigates to `/dashboard`). `web/dist/` was cleaned after verifying `npm run build:web` so `npm test` (`src/qa-scenarios.test.js`) stays green.
- Documented minor Express/Worker differences remain unchanged from project memory (`KI-002` and `runtime-parity.md`): Express redirects use relative `Location` headers (`/dashboard`, `/login`, `/products`) whereas Worker uses absolute URLs (`http://.../dashboard`, `/login`, `/products`), and unsupported API HTTP methods return 404 on Express vs 405 on Worker.
- By approved design (`proposal.md` / `design.md`), multi-admin account management UI, self-registration, OAuth, and password reset flows are out of scope for this change.
- The lightweight React static-markup hook harness logs React key warnings on top-level array children during server-rendered test ticks; JSX source keys and runtime behavior are unaffected.

**Overall recommendation:** PASS
