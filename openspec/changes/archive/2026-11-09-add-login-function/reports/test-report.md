Note: Iteration 1's report prose used shorthand names (`pma_session`, `ADMIN_*`, `"Invalid credentials"`), whereas the implementation and tests use `admin_session`, `AUTH_BOOTSTRAP_*`, and `"Invalid username, email, or password"`; per retest scope, that prior prose discrepancy was corrected in this report and not filed as a defect.

- **Retest outcome:** Browser verification uncovered two high-severity defects (`DEF-001` Logout from `/products`, `/brands`, or `/categories` redirects to `/login` instead of `/dashboard`; `DEF-002` narrow-width `.nav` horizontal overflow clips `Categories` and pushes `.nav-auth` `Login`/`Logout` completely off-screen at `390x844`) and one medium-severity layout defect (`DEF-003` unstyled inline `<form>` on `/login`). Note that `src/login-qa.test.js` did not catch `DEF-001` because its synchronous static-markup router harness batched `setUser(null)` and `navigate("/dashboard")` into one render, unlike real React 19 + React Router 7 in Chrome.

## Known limitations

- Live Cloudflare `wrangler dev` preview was not started because `.dev.vars` is absent; Worker HTTP, redirect, cookie, and `ASSETS` behavior is covered by `src/qa-scenarios.test.js`, `src/brand-qa.test.js`, and `src/login-qa.test.js`.
- Pre-existing Express static-middleware behavior: when `web/dist/index.html` exists on disk and Express runs with `dev: false`, `express.static(path.join(webDir, "dist"))` serves `web/dist/index.html` (HTTP 200) on `GET /` before `app.get("/", ...)` emits HTTP 302 (after which client-side `<Route path="/" element={<Navigate to="/dashboard" replace />} />` navigates to `/dashboard`). `web/dist/` was cleaned after verifying `npm run build:web` so `npm test` stays green.
- Documented minor Express/Worker differences remain unchanged from project memory (`KI-002` and `runtime-parity.md`): Express redirects use relative `Location` headers (`/dashboard`, `/login`, `/products`) whereas Worker uses absolute URLs, and unsupported API HTTP methods return 404 on Express vs 405 on Worker.
- By approved design (`proposal.md` / `design.md`), multi-admin account management UI, self-registration, OAuth, and password reset flows are out of scope for this change.
